# 并行度的内点：NPU 上的切分边际成本

> **问题**：在 NPU 上，切分是不是「卡越多越快」？
>
> **结论**：不是。每加一档并行度都要多付一笔与计算量无关的固定开销 `b`。
> 该开销与计算项的收缩相遇，使最优并行度**存在内点**，且位置随请求长度移动。
> 对短请求，用满 8 卡比最优档位慢 19–41%。
>
> **状态**：机制有实测支持（`b` 三点、3.45σ）；内点的**精确位置**依赖
> `b(N)` 的形状，而形状尚未测准。本文给出的是判定方案，不是最终数值。

纯标准库，无第三方依赖。

```bash
python3 derive_b.py                      # 从 13 点实测反解 b
python3 -m unittest discover -s tests    # 16 项判定逻辑测试
```

## 一、为什么这件事在 NPU 上成立、在 GPU 上不成立

文献里的并行度选择都建立在一条假设上。Alpa（OSDI'22）说得最直接：

> For compute costs `c_v`, we set all of them as zero...
> All parallel algorithms always evenly divide the work to all devices, so
> **all parallel algorithms of one operator have the same arithmetic complexity**.

即：算的 FLOPs 不随并行度变，所以计算代价与并行度无关，并行度越大越快
（直到通信主导）。

**在 NPU 上这条不成立**，但不是因为 FLOPs 变多——FLOPs 确实不变。
变的是**下发次数**：

| 来源 | 为什么随 N 增长 | 依据 |
|---|---|---|
| 逐 kernel 下发 | 动态 shape 下每个算子拆成 InferShape / Tiling / AllocMem / Launch 四个 Host Kernel；复杂算子 **Tiling 可达数十微秒** | CANN 动态 Shape 图调度文档 |
| 集合通信轮次 | `τ = s·α`；Ring 是 `N−1` 轮、Butterfly 是 `log₂N` 轮 | HCCL 的 α–β 模型 |
| 未切分的 KV 搬运 | CP 只切 Q，每卡都读整段 KV ⇒ 聚合访存 `×(1+N)/2` | 阶段模型的 `volume_bytes` |

**三条都是「切分自身带来的代价」。** 所以

```
T(N) = b(N) + C·N^(-ρ)
       ↑ 随 N 增    ↑ 随 N 减
```

这两项相遇之处就是内点。

## 二、实测证据

`data/attn_mtgr_cp13.csv` 是 MTGR 注意力段的 13 个长度点、三档并行度实测（256–16384，跨 64 倍）。
`derive_b.py` 按 `T = b + θ₁L + θ₂L²` 逐档反解，权重取 `1/T`：

| 并行度 | `b` (ms) | 标准误 (ms) | MAPE |
|---|---|---|---|
| cp2 | 8.799 | 0.467 | 6.17% |
| cp4 | 10.712 | 0.753 | 8.74% |
| cp8 | 12.315 | 0.906 | 10.62% |

跨档差异：

| 对比 | Δ | SE(Δ) | 显著性 |
|---|---|---|---|
| cp2 → cp4 | +1.913 ms | 0.886 | 2.16σ |
| cp4 → cp8 | +1.604 | 1.178 | **1.36σ（不显著）** |
| **cp2 → cp8** | **+3.517** | **1.020** | **3.45σ ✓** |

**能说的**：`b` 在 cp2 与 cp8 之间有显著差异（+40%），且四种拟合形式
（三项式 / tile / 纯幂律 / 无一次项）一致给出 1.33×–1.43× 的上升。
**不能说的**：`b` 单调上升——cp4→cp8 这一段不显著。

## 三、形状未知，而形状决定结论

`b(N)` 只有三个值，用它们去定形状是不够的。并且数据本身已经在暗示**不是线性**：

| 区段 | 每卡增量 |
|---|---|
| cp2 → cp4 | +0.956 ms/卡 |
| cp4 → cp8 | **+0.401** ms/卡 |

比值 **0.42**（线性应为 1.00）。用加权 rms 比较四种形状穿过这三点：

| 形状 | 加权 rms |
|---|---|
| linear | 343 μs |
| sqrt | 214 |
| log | 131 |
| **saturated** | **62** |

数据**弱偏好次线性**。而次线性会把内点推向更小的 N。

### 但定性结论对形状稳健

用四种形状各自求内点（`ρ=0.83`，8 卡上限）：

| 形状 | L=256 | L=2048 | L=8192 | L=16384 |
|---|---|---|---|---|
| saturated | N\*=1，损失 **40.8%** | N\*=2，20.6% | 8，0% | 8，0% |
| log | 1，40.5% | 2，20.3% | 8，0% | 8，0% |
| sqrt | 1，35.6% | 2，19.8% | 8，0% | 8，0% |
| linear | 2，28.5% | 2，18.6% | 8，0% | 8，0% |

**四种形状一致认为：短请求应少用卡（损失 19–41%），长请求用满 8 卡无损失。**
只有 L=256 的档位在 1 与 2 之间摆动，损失量级不变。

所以本工作的定位是：**定性结论可写，定量位置待测。**

## 四、判据不能是「认出形状」

这是本文最重要的一处设计决定。形状标签在噪声下会判**错**，不只是判不出。
以真值 `saturated` 为例（9 个点、σ 逐步加大）：

| σ (ms) | 判出的标签 | 判对 | 与次优的 rms 比 |
|---|---|---|---|
| 0 | `saturated` | ✓ | 3.7e10 |
| 0.15 | `sqrt` | ✗ | 1.0 |
| **0.3** | **`linear`** | **✗** | **1.0** |

σ=0.3 时判成 `linear`，而真值是 `saturated`。而 `b` 的标准误实测为 470–906 μs，
σ=0.3 还属乐观。

**改用边际斜率 `b'(N)` 这个数**。同一批噪声下：

| 真值 | `b'(8)` 真值 | σ=0.5、单次测量 |
|---|---|---|
| linear | 0.586 ms/卡 | 0.58 ± 0.02 |
| sqrt | 0.104 | 0.10 ± 0.02 |
| saturated | 0.020 | 0.03 ± 0.02 |

**即使噪声 0.5 ms、只测一次，三者也能分开。** 因为斜率是对全部点平滑后的量。
`tests/test_marginal.py` 里有一项专门断言这一点。

### 第二个陷阱：不能只在单个 N 处比较

| N | b(N) | b'(N) | 边际节省 | b' > 节省 |
|---|---|---|---|---|
| 1 | 8.22 | 0.586 | 2.822 | 是 |
| **2.36** | 9.00 | 0.586 | 0.60 | ← 最优 |
| 8 | 12.32 | 0.586 | 0.063 | 是 |

在 N=8 处 `b' >> 节省`，看起来「早已过内点」，但最优点在 2.36。
判据必须**扫全区间**取极值。`inner_point_exists` 的第一版就犯了这错，已修并加回归测试。

## 五、要测什么

| N | 作用 | 已有 |
|---|---|---|
| **1** | 内点可能就在 1~2 之间 | ✗ 必补 |
| 2, 4, 8 | 基准 | ✓ |
| **3** | 区分「每档 +Δ」与「每档 +Δ/√N」 | ✗ 必补 |
| **6** | 填 4→8 空档，检验线性 | ✗ 必补 |

最小集 **{1,2,3,4,6,8}**：六点、2 参数、留 4 个自由度做拟合优度检验。

每点重复 **5 次**：`Δ(6→8) ≈ 1.17 ms`，单次 SE 1.24 ms（0.9σ）不可判；
5 次降到 0.56（2.1σ）。成本 **9–30 次计时**。

只测注意力段——它是唯一 L² 的段，其余段的时间占比与 `b` 相比太小，会被噪声淹没。

完整流程见 [`方案-并行度内点.md`](方案-并行度内点.md)。

## 六、三条证伪条件

| 观测到 | 结论 |
|---|---|
| `b'(8)` 的 95% CI 含 0 | `b` 在 N≥4 后饱和 ⇒ 不存在内点，加卡永远对 |
| `b'(8)` 显著但用满 8 卡损失 < 5% | 内点在 8 卡之外 ⇒ 本机范围内无需考虑 |
| L=256 时 cp8 明显快于 cp1（>1.11×） | kernel 下限不存在 ⇒ 短请求的结论不成立 |

**九次计时就能判定。** 第三种情形是本文尚未验证的关键假设：
仿真里 `min_stage_s ≈ 60 μs` 是估的，它决定短请求收益的大小。

## 七、与已有工作的边界

| 不能说 | 为什么 |
|---|---|
| ❌「提出并行度搜索算法」 | Alpa 的 intra-op pass（ILP）、nnScaler（约束搜索）、FlexFlow（图划分）已做透 |
| ❌「Amdahl 定界」 | 1967 年 |
| ❌「CP 换长度换 batch」 | RecSys'25（[arXiv:2508.04711](https://arxiv.org/abs/2508.04711)）的结论 |

**增量只有三条**：

1. `b` 是**并行度的函数**，且它的**形状需要测**。Alpa 假设它与并行度无关
   （「all parallel algorithms have the same arithmetic complexity」），
   而 NPU 上 FLOPs 没变但下发次数变了。
2. 该负项与 `N^-ρ` 相遇使净收益**非单调**，故并行度不是「越大越好」，
   而是需要**在线求解的整数变量**，位置随请求长度移动。
3. 判据是 `b'(N)`，它可由有限几次测量估计，且**对形状假设不敏感**——
   这使方案在数据不足时仍可执行。

## 八、文件

```
marginal.py              判定逻辑（形状拟合、斜率、内点求解、饱和判据）
derive_b.py              从 13 点实测反解 b 并给出标准误
data/attn_mtgr_cp13.csv  13 个长度点 × 三档并行度
方案-并行度内点.md        完整方案：测量集、重复次数、判定树、证伪条件
tests/test_marginal.py   16 项，含「形状标签在噪声下会判错但斜率仍准」
```

`marginal.py` 的接口：

| 函数 | 用途 |
|---|---|
| `fit_shape(points)` | 四种形状的最小二乘，按 rms 排序；少于 4 点直接拒绝 |
| `identify_shape(points)` | 取最优；与前一名差距不足则返回 `ambiguous` |
| `slope_at(fit, n)` | **主判据** |
| `optimal_degree(fit, C, rho)` | 扫全区间求内点 |
| `optimal_degree_within(fit, C, cards)` | 本机卡数约束下的最优档位与损失 |
| `inner_point_exists(fit, C)` | 内点是否落在给定区间内 |
| `is_saturated(times)` | 该段是否已触及 kernel 下限 |
